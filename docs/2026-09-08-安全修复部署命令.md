适用路径：`/home/zhenghe.bao/LegalOS/LegalOS`。沿用已存在的 `legalos-api`、`legalos-web`，不操作其他 PM2 进程。

本文件是发布步骤，执行前须确认对应修复已经推送且验收通过。保留服务器现有 `.env`；CRM 可以继续关闭，不需要填写新的 CRM 凭证。不要执行 seed，不使用 `npm audit fix --force`。

如果历史上执行过使用默认密码的旧 seed，需要由管理员检查并轮换相应账户密码。此次代码修复阻止重复初始化覆盖现有账户，不会擅自修改线上用户密码。

## 更新、构建与重启

在服务器终端整体执行。命令在子 shell 中运行，检查失败会停止部署，不会因 `set -e` 直接结束 SSH 登录 shell。

```bash
bash <<'DEPLOY'
set -euo pipefail
release_root=/home/zhenghe.bao/LegalOS/LegalOS
cd "$release_root"

if [ -n "$(git status --porcelain)" ]; then
  git status --short
  echo '工作区存在修改，已停止；请先确认，不要强制覆盖。'
  exit 1
fi

git fetch origin main
git checkout main
git merge --ff-only origin/main
git log -1 --oneline
node --version

cd "$release_root/api"
npm ci
npx prisma generate
npm run typecheck
npm run build

# 此次代码修复没有新增迁移，正常应显示 schema is up to date。
# 若有未应用或失败的迁移，此命令非零退出，部署在重启前停止。
npx prisma migrate status

cd "$release_root/web"
npm ci
npm run typecheck
npm run build

pm2 restart legalos-api
pm2 restart legalos-web

api_ready=false
for attempt in $(seq 1 30); do
  api_code=$(curl --silent --output /dev/null --write-out '%{http_code}' \
    --max-time 2 http://127.0.0.1:3000/api/auth/me || true)
  if [ "$api_code" = 401 ]; then
    api_ready=true
    break
  fi
  sleep 1
done
if [ "$api_ready" != true ]; then
  pm2 logs legalos-api --lines 60 --nostream
  echo 'API 未通过启动探测，请排查；尚未执行 pm2 save。'
  exit 1
fi

curl --fail --silent --show-error --max-time 10 \
  --output /dev/null http://127.0.0.1:5173/login
pm2 list
pm2 logs legalos-api --lines 40 --nostream
pm2 logs legalos-web --lines 30 --nostream
echo '基础启动探测完成。请完成浏览器业务验收，确认后单独执行 pm2 save。'
DEPLOY
```

`/api/auth/me` 无凭证返回 401 只证明服务与认证入口正常，不等价于真实业务验收。浏览器还需验证：公司账号登录、工单列表/详情、合同附件上传下载、AI 搜法完整报告与历史恢复。

验收后保存现有进程清单：

```bash
pm2 save
```

## 数据库与运行环境边界

- 不因为 CRM 源码存在就启用 CRM。`CRM_A1_ENABLED` 未设置/为 `false` 时仍保持关闭；`CRM_MOCK` 不在生产开启。
- 本轮没有修改 Prisma schema 或新增迁移。如果服务器 28 个已有迁移均已应用，则不需要为了这次代码更新再执行数据库迁移或专项迁移备份。日常备份策略仍应保留。
- 若 `migrate status` 发现待执行迁移，先停止本流程，核对差异、备份与恢复方案后再安排维护窗口；不要直接对生产运行 `migrate dev`。
- 历史 PM2 输出中的 Web 使用 `npm run dev -- --host`。以上步骤保留该启动方式，不会自动切换到生产静态托管。`npm run build` 是构建验证，并不表示当前 PM2 已改为服务 `dist`；正式静态托管应单独调整和验收。
- 已有源码与构建原地更新时，线上服务可能继续读取变化中的资源；更严格的零停机发布需使用独立版本目录和流量切换，本流程不承诺零停机。
