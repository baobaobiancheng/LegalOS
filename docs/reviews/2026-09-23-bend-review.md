# 已确认业务约束复核

日期：2026-09-23。代码基线：`67ff9bc`。本报告记录本轮代码修改与本地验证，不代表生产部署已完成。

本轮借用 Bend 的“声明不变量、构造反例、运行检查”方法，用现有 TypeScript 测试验证实际服务入口。不引入 Bend 运行依赖，也不声称已经形式化证明整个项目正确。

## 修复与补齐

| 不变量 | 原实现的反例 | 本次处理 |
|---|---|---|
| 无权用户的合同上传不能进入落盘阶段 | Multer 接收文件后，Service 才检查工单权限 | 新增 `ProjectFileAccessGuard`，在 Multer 前校验 UUID、工单存在和对象权限 |
| 上传写入时仍须拥有当前工单权限 | 文件解析期间工单被转派，原法务仍可写文件、正文和消息 | 父行锁后重读工单，复用 `ManageFile` 权限检查；失败保留 403/404 并清理文件 |
| CRM 完成必须伴随确认文件和交付入队 | 通用 PATCH 可将工单改为“已回传”，却没有审核完成信息和 Outbox | PATCH 拒绝 CRM 完成迁移，要求走现有正式回传用例 |
| 人工确认后的结论不能变成未经确认的新内容 | PATCH 可修改 `result`，CRM Worker 随后读取修改后的结论 | 初查及锁内复查均阻止修改人工已完成的结论；保留相同值重放和风险更新 |
| AI 并发、排队和计时器配置必须有效 | NaN 导致不执行，Infinity/小数破坏并发上限，计时器溢出 | 启动时拒绝非法配置；单次排队时间也做边界检查 |
| 执行结果失败不等于执行器已经停止 | `result` 拒绝后提前释放会话槽位；外部取消监听在部分结束路径残留 | 槽位由 `done` 释放；成功、取消、超时均清理监听；删除未使用的子进程宽限期常量与过时说明 |

上传前授权对应 P1-06 已确定但未接入的 Guard 方案。队列对应 P1-02 的并发和取消约束。CRM 沿用既有正式完成事务，未新增交付协议或数据库状态。
