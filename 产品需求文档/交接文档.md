# LegalOS 项目交接文档

更新日期：2026-09-17。面向首次接手的开发、测试和运维人员。代码核对基线：`9687a3e`（管理员统一导航）。本文是接手入口，不取代接口契约、源码和运行环境核验。

## 1. 先了解项目

LegalOS 是企业内部法务工作台：业务人员提出法律咨询或提交合同，AI 负责受控咨询、法规/类案检索、合同起草和审查，普通法务处理指派工单，法务领导负责兜底分配，管理员维护账号、组织和职责规则。

必须分清两条路由：

- **AI 意图路由决定使用什么能力**：`general`、`law_search`、`similar_case`。自动识别失败时允许重试或手动选择，不悄悄降级成无检索回答。
- **人工职责路由决定由谁处理**：依据申请人的钉钉组织、启用的业务职责规则和有效法务账号，不让模型选择人员，不再按专业领域标签分配。

仓库地址：`http://git.100credit.cn/zhenghe.bao/LegalOS.git`，主分支 `main`。仅供授权的公司内部人员访问。GitLab、JumpServer、数据库、CAS、钉钉、百鉴及模型账号权限分别申请，Git 仓库权限不等于其他系统权限。

### 接手顺序

1. 取得仓库和测试环境权限，阅读本文及产品总览，确认业务负责人和运维联系人。
2. 按第 4 节启动独立开发环境，跑离线检查；不要复制生产数据库到个人设备。
3. 用业务、普通法务、领导、管理员四种测试身份走验收清单。
4. 核验外部系统配置和真实调用；最后再接手发布权限。

## 3. 当前架构和关键代码

技术栈为 Vue 3 / Pinia / Vue Router / Vite，NestJS 10 / TypeScript / Prisma 6，MySQL 8。Node 采用 24；API 声明最低支持 22.19。前后端独立安装锁定依赖。

```text
浏览器 → Vue → /api → NestJS 限流、认证、角色及工单权限
                         ├─ MySQL：账号、工单、规则、运行状态、审计、Outbox
                         ├─ 通用咨询/意图识别 → LLM 网关
```

## 4. 从零启动开发环境

### 4.1 准备依赖和配置

安装 Node 24、npm、Git、MySQL 8。先创建**独立开发库**，为它配置最小权限数据库账号。以下命令不面向现网：

```bash
git clone http://git.100credit.cn/zhenghe.bao/LegalOS.git
cd LegalOS
npm ci
npm --prefix api ci
npm --prefix web ci
cp api/.env.example api/.env
```

在 MySQL 中创建开发库，例如：

```sql
CREATE DATABASE legalos_dev CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

编辑 `api/.env`：至少填写开发库 `DATABASE_URL` 和独立随机 `JWT_SECRET`，不要保留示例密码。开发环境可用 `DINGTALK_MOCK=true`、`CRM_A1_ENABLED=false`；不要借用真实回传配置。需要本地密码登录时保持 `CAS_ENFORCED=false`，设置 `SEED_ADMIN_PASSWORD` / `SEED_BUSINESS_PASSWORD`（至少 12 位并包含大小写、数字和符号）。它们只用于新建账号，seed 不修改既有账号密码。

随后执行：

```bash
cd api
npx prisma generate
npx prisma migrate deploy
npm run prisma:seed
cd ..
npm run dev
```

新库用已提交迁移即可；只有开发新表结构时才用 `prisma migrate dev` 创建新迁移。生产禁止 `migrate reset`、`db push`、修改已应用迁移或随意重跑 seed。

前端 `http://localhost:5173`，后端 `http://localhost:3000/api`。Vite 将 `/api` 代理到 3000；本地换端口时用 `VITE_API_TARGET`。独立前后端地址需同步 `WEB_ORIGIN` 和 Cookie 配置。当前无 Swagger 页面，不要以 `/api/docs` 不存在判断服务坏了。

### 4.2 配置交接表

只交接变量名、权限负责人和密钥获取渠道，真实值走公司受管凭证渠道。不要提交 `.env`、导出 PM2 全量环境或在日志中打印密钥。

| 能力 | 主要变量 | 注意事项 |
|---|---|---|
| 数据库/登录 | `DATABASE_URL`、`JWT_SECRET`、`PORT`、`WEB_ORIGIN` | JWT 轮换会影响会话；数据库不得指向生产做测试 |
| CAS | `CAS_HOST`、`CAS_PROJECT_CODE`、`CAS_REDIRECT_URL`、`CAS_ENFORCED`、`CAS_ROLE_MAP`、`CAS_DEPT_MAP` | 生产不启用 `CAS_BYPASS`；个人角色映射可覆盖角色，必须审批 |
| 钉钉 | `DINGTALK_APP_KEY/APP_SECRET/AGENT_ID/ROBOT_CODE/SCENE_TEMPLATE_ID`、`DINGTALK_MOCK` | 需要通讯录及群相关权限；同步组织、关联账号、应用规则是不同步骤 |
| 通用模型 | `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` | 意图识别也依赖此链路；保留的 `CODEX_*` 配置名不代表仍运行 Codex CLI |
| DSH 模型 | `DSH_LLM_PROVIDER/BASE_URL/API_KEY/MODEL`、`DSH_MODEL_CONTEXT_WINDOW`、`DSH_MODEL_MAX_OUTPUT_TOKENS` | 支持独立 DeepSeek 路由；缺省回退关系以服务端实现为准，模型 ID/额度须向供应商核验 |
| 百鉴 | `BAIJIAN_MCP_URL/APP_KEY/APP_SECRET` | 模型能回答不等于有百鉴正文；必须独立验证 |
| AI 限制 | `AI_EXECUTION_ENABLED`、`AI_EXECUTION_CONCURRENCY/QUEUE_MAX_SIZE/QUEUE_TIMEOUT_MS` | Kill Switch 可停模型调用，不替代人工流程；提高并发须压测 |
| 文件/会话 | `CONTRACT_STORAGE_DIR`、`CONTRACT_TEMPLATE_STORAGE_DIR`、`DSH_HOME` | 使用持久目录；多实例共享文件存储；备份不能只备 MySQL |
| CRM | `CRM_A1_ENABLED/APP_ID/SECRET/ALLOWED_IPS`、`CRM_MOCK` | 暂未联调可保持 A1 关闭、Mock 关闭，不必先配置凭证 |
| 审计/交付 | `AUDIT_HMAC_SECRET`、`OUTBOX_*` | HMAC 变更影响历史核验；Outbox 失败先查原因再人工重放 |

`.env.example` 有历史说明，不能当成生产配置模板直接覆盖现网。若曾在聊天或旧资料暴露密钥，即使从本次提交剔除，也应由凭证负责人轮换。

### 发布步骤

1. 固定已审核提交号，确认工作树和目标服务；服务器 `.data/`、`.env.backup.*`、`.env.save` 等现存本地文件不覆盖、不提交，也不为清空状态而删除。
2. `git fetch origin main` 后核对差异，再 `git merge --ff-only <已批准提交号>`。失败立即停止，禁止 force/reset 覆盖服务器改动。Git 密码直接在终端输入，不发聊天。
3. 若仅本次管理员导航变更：Web 执行 `npm ci`、`npm run typecheck`、`npm run build` 后仅 `pm2 restart legalos-web`；不需要数据库迁移、API 重启或数据库备份。
4. 若涉及 API：在 `api` 执行 `npm ci`、`npx prisma generate`、类型检查和构建；检查 `npx prisma migrate status`。它因待迁移返回非零时，不能直接归因于 SSH 故障。
5. **有待执行数据库迁移时另开维护窗口**：先核对 SQL、备份数据库及受影响文件、确认恢复方案，再执行 `npx prisma migrate deploy`。没有迁移不要为了发布 UI 做无关数据库操作。
6. 按变更范围重启对应 PM2 进程。仅在明确修改环境变量时才评估 `--update-env`，不要顺手覆盖现有进程环境。
7. 检查 PM2 不再持续重启、HTTP 和实际浏览器流程正常后 `pm2 save`，记录提交、迁移、构建、重启、验收和回滚点。

未登录请求 `GET /api/auth/me` 返回 401 是鉴权预期，只能证明 API 可响应，不能证明业务链路健康。验收应从浏览器真实登录开始。日志按问题时间和 `requestId` 定位，避免将含合同/个人信息的全量日志外发。

### 备份与回滚

MySQL、合同持久目录、审定模板、DSH 会话目录都要有备份策略。合同默认 `api/storage/contracts`，模板默认 `api/storage/contract-templates`；DSH 未配 `DSH_HOME` 时在 `api/.tmp/dsh-home` 下使用版本化会话目录。实际路径以环境配置为准，`.tmp` 名称不代表可随意清理。

回滚应用应使用经审核的回退提交或独立旧版本目录，重装匹配锁文件并重新构建；保留现场和日志。Prisma 没有自动“逆向 deploy”，含数据库结构变化时先确认旧代码兼容性，不能只回退代码或直接恢复整库覆盖新增业务数据。

## 9. 常见问题定位

| 现象 | 优先检查 |
|---|---|
| 法务看不到工单 / 403 | `/auth/me` 角色、工单 `legalBpId`、对象权限策略；未指派不可见可能是正确行为 |
| 职责显示待同步/待关联 | 同步批次是否成功、部门是否启用、CAS 账号/角色/钉钉绑定是否一致、规则是否已应用 |
| AI 意图识别失败 | `LLM_*` 链路，不仅是 DSH 模型；允许手动选择，不跳过证据检查 |
| AI 有进度但无有效报告 | 供应商正文、证据门槛、模型截断、工具预算与任务终态；不能用隐藏报错掩盖 |
| CRM 审核完成但未送达 | B1 Adapter 是否真实实现、Outbox 重试/死信、法务确认文件及存储可见性 |
| SSE 固定时间断开 | 浏览器、Vite/反代、NestJS、模型各层超时及取消传播，检查是否有重复执行 |
| 文件丢失 | PM2 cwd、持久目录/共享卷、权限和备份，不只是数据库记录 |
| 内存看起来很满 | `free -h` 的 available、swap 和各进程 RSS；Linux buff/cache 可回收，PM2 npm 包装进程内存不等于子进程总量 |
