## 2. 对实现的要求(ConsultationChatService 必须遵守)

1. 请求体:`{ model, messages, stream: true, max_tokens }`,`max_tokens` = 输出预算(**含思考**),不能只按答案长度设。
2. 响应解析:
   - 忽略空行;每行 `data: ` 前缀后是 JSON(最后一行 `data: [DONE]` 是纯文本,不是 JSON)。
   - `delta.reasoning` → 写入 thinking 流。
   - `delta.content` → 写入 stdout(text)流。
   - 首帧 role 标记帧(只有 `content:""`)不产生输出。
   - 流结束后,答案 = content 增量累计(与 SSE 现有 done.finalText 对齐)。
3. 超时:推理模型思考时间长(实测整段 28s+),前端 SSE 空闲超时已是 120s;后端请求级超时需 ≥ 思考上限 + 内容生成。
4. 日志:不打印 prompt、messages、key、合同正文;只记 projectId/runId/耗时/token/HTTP 状态/请求 id。
5. 环境变量:`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` / `CONSULT_OUTPUT_TOKEN_RESERVE`(等)。

## 4. 原始证据(节选)

非流式 0.2:`message.content="测试成功"`;`message.reasoning="1. **分析请求：**..."`;`usage: completion_tokens=93`。

流式 0.3:
- 首帧 `data: {"...","delta":{"role":"assistant","content":""},...}`
- 思考帧 `data: {"...","delta":{"reasoning":"1"},...}` → `"分析"` → ...
- 内容帧 `data: {"...","delta":{"content":"测试"},...}`(第 229 行)→ `"成功"`(第 231 行)
- 末帧 `data: [DONE]`

0.4(max_tokens=50):`message.content=null`,`reasoning` 长文,`finish_reason:"length"`,`completion_tokens=50`。
