## 2. 方式一:直接调用模型(OpenAI 兼容接口)

适合:项目里直接发聊天/生成请求,不依赖 Codex 的 agentic 能力。

### 2.1 配置(各项目 `.env`)

```bash
LLM_BASE_URL=http://api-cybotforge-pre.brapp.com/v1
LLM_API_KEY=<共享key>
LLM_MODEL=glm-5-2
```

### 2.2 调用示例

**curl(非流式)**:

```bash
curl -s http://api-cybotforge-pre.brapp.com/v1/chat/completions \
  -H "content-type: application/json" \
  -H "authorization: Bearer $LLM_API_KEY" \
  -d "{\"model\":\"$LLM_MODEL\",\"messages\":[{\"role\":\"user\",\"content\":\"你好\"}],\"max_tokens\":512}"
```

**Python(openai SDK,支持流式)**:

```python
import os
from openai import OpenAI

client = OpenAI(
    base_url=os.environ["LLM_BASE_URL"],
    api_key=os.environ["LLM_API_KEY"],
)
stream = client.chat.completions.create(
    model=os.environ["LLM_MODEL"],
    messages=[{"role": "user", "content": "你好"}],
    stream=True,
)
for chunk in stream:
    delta = chunk.choices[0].delta
    if delta.content:
        print(delta.content, end="")
```

**Node(fetch,流式)**:

```js
const resp = await fetch(`${process.env.LLM_BASE_URL}/chat/completions`, {
  method: 'POST',
  headers: {
    'content-type': 'application/json',
    authorization: `Bearer ${process.env.LLM_API_KEY}`,
  },
  body: JSON.stringify({
    model: process.env.LLM_MODEL,
    messages: [{ role: 'user', content: '你好' }],
    stream: true,
  }),
});
const reader = resp.body.getReader();
// 逐行解析 `data: {...}` SSE 事件,取 choices[0].delta.content
```

### 2.3 重要:`glm-5-2` 是推理模型

- 流式输出**先 `delta.reasoning`(思考过程),后 `delta.content`(正式答案)**——取答案要等 `content` 字段,别把 reasoning 当结果。
- **`max_tokens` 要给够**(如 ≥512),否则思考过程会占满长度,拿不到正式答案。
- 非流式响应同样:`choices[0].message.content` 为答案,`reasoning` 字段为思考。

## 3. 方式二:底层为 Codex 调用(需要 agentic 能力)

适合:合同生成/审查这类要**读写文件、跑命令、多步操作**的任务(LegalOS 就是这么用的)。

### 3.1 服务器已就绪

`/etc/codex/config.toml` 已配好,指向网关:

```toml
model = "glm-5-2"
model_provider = "baorong"

[model_providers.baorong]
name = "百融大模型网关(预发)"
base_url = "http://api-cybotforge-pre.brapp.com/v1"
wire_api = "responses"
env_key = "CODEX_API_KEY"
```

> 说明:codex-cli ≥0.95 只支持 `wire_api = "responses"`,网关已兼容该协议,无需降级。

### 3.2 各项目只需设置 key

自己的进程环境里设:

```bash
export CODEX_API_KEY=<共享key>
```

然后直接跑 `codex exec`,底层就是 glm-5-2:

```bash
echo "一句话介绍你自己" | CODEX_API_KEY=$CODEX_API_KEY \
  codex --strict-config -a never -c shell_environment_policy.inherit=none \
  exec --skip-git-repo-check --ephemeral --ignore-user-config -
```

### 3.3 应用内调用(流式)

应用里 spawn `codex exec`,读 `stdout` 流式返回前端(参考 LegalOS `api/src/common/services/codex.service.ts`:队列、工作区隔离、超时终止、取消)。

### 3.4 换模型

- 直接调用方式:改 `LLM_MODEL`。
- Codex 方式:改 `/etc/codex/config.toml` 的 `model`,或用 `codex exec -m <模型名>` 覆盖。
- 注意:换了模型要先确认该模型在共享 key 授权内。

## 4. 注意事项

1. **生产环境**:网关 `api-cybotforge.brapp.com` **仅允许生产 k8s 访问**,不允许个人电脑/开发机;生产 apikey 授权给**业务名称**(非 casid),需单独向推理平台 TL 申请。
2. **key 安全**:共享 key 只放服务器各项目 `.env`,**不进 git、不进文档、不写日志**。若项目要独立计费/审计,建议各自找 TL 申请独立 key。
3. **模型授权**:当前共享 key 未授权 `qwen3-5` 与 embedding/rerank;要用需另开。
4. **模型真实路由**:网关 `glm-5-2` 名下的真实基础模型以推理平台 TL 答复为准(自述不可靠)。
