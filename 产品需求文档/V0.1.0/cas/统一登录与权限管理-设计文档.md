## Problem Statement

法务AI平台需要统一入口登录，按角色（法务 BP / 法务负责人 / 业务人员 / 管理员）进入不同的工作端。当前公司有钉钉/企微通讯录可同步人员信息，但 v0.0.1 阶段不依赖外部系统，先以种子用户跑通认证链路，后续版本对接通讯录。

## Status Quo

目前公司内部法务协同没有统一的认证入口——业务人员通过 CRM、钉钉、邮件分别获取法务支持。通讯录在钉钉/企微中，但无 API 级对接经验。v0.0.1 阶段选择种子用户方案，降低外部依赖风险。

## Target & Wedge

**最窄可用版本**：数据库种子脚本预置 4 个账号（每角色一个），用户登录后 JWT 签发，前端根据角色自动跳转对应端首页。不需要注册页面、不需要忘记密码。

## Constraints

- v0.0.1 只有种子用户，无注册/忘记密码流程
- 无外部 SSO 依赖，纯 JWT 自建
- NestJS + Prisma + MySQL + Vue 3 + Element Plus
- 后续 v0.1.0 对接通讯录时只替换 AuthService，不动前端
- 安全加固（v0.0.1）：
  - 登录速率限制：`@nestjs/throttler`，每 IP 5 次/分钟
  - 连续 5 次失败锁定 30 分钟：User 表 `failedAttempts` + `lockedUntil`，Prisma 原子 `increment` + `where` 防竞态
  - refreshToken 旋转：数据库 `RefreshToken` 表存 token hash + `jti`，使用后立即标记失效并签发新 token 对

## Premises（全部确认）

1. v0.0.1 用数据库种子脚本预置账号，不对接通讯录 ✓
2. JWT access token (15min) + refresh token (24h)，不做 session ✓
3. 四角色映射三端：business→业务端、legal_bp/legal_lead→法务端、admin→管理端 ✓
4. 审计日志 v0.0.1 只记录登录成功事件（LoginAudit，user 外键必填），失败尝试仅靠速率限制计数，不做独立失败审计表 ✓
5. 初始管理员通过种子脚本创建，无注册页面。v0.0.1 密码硬编码在 seed.ts，生产部署前改环境变量 ✓
6. 全局注册 JWT AuthGuard，所有端点默认需登录，公开端点（`/login`、`/refresh`）用 `@Public()` 豁免 ✓

## Approaches Considered

| | Approach A: JWT 双 Token | Approach B: Session + Redis | Approach C: 钉钉免登 |
|---|---|---|---|
| Effort (human/CC) | 2d / 20min | 3d / 30min | 1w / 1h |
| Dependencies | MySQL only | + Redis | + 钉钉开放平台 |
| 前端复杂度 | Med（token 刷新） | Low（cookie 自动） | Low（扫码） |
| 升级 SSO 成本 | 只换 AuthService | 需改整个认证层 | 无需升级 |
| v0.0.1 适配度 | ★★★ | ★★ | ★ |

## Recommended Approach

**Approach A: JWT 双 Token + 种子用户**。NestJS `@nestjs/jwt` + `@nestjs/passport` 原生支持。后续升级 SSO 只需替换签发逻辑。

### Token 传输策略

- **accessToken**：response body 返回，前端存 Pinia state（内存，页面刷新后丢失，refresh 重新获取）
- **refreshToken**：httpOnly + Secure + SameSite=Strict cookie，自动携带，防 XSS

### 技术细节

**后端 API 端点**

```
POST /api/auth/login
  Body: { username: string, password: string }
  → 检查账号是否锁定 (lockedUntil > now → 423)
  → bcrypt 校验
  → 成功: 重置 failedAttempts，签发 token 对，记录 LoginAudit
  → 失败: 原子递增 failedAttempts，≥5 则设置 lockedUntil
  → Response 200: { accessToken, user: { id, username, role, displayName } }
         + Set-Cookie: refreshToken (httpOnly)
  → Response 401: { error: "用户名或密码错误", code: "INVALID_CREDENTIALS" }
  → Response 423: { error: "账户已锁定，请30分钟后再试", code: "ACCOUNT_LOCKED", lockedUntil }

POST /api/auth/refresh
  Cookie: refreshToken=<token>
  → 查 RefreshToken 表验证 hash + 未过期 + 未使用
  → 标记旧 refreshToken 为已使用
  → 签发新 accessToken + 新 refreshToken（旋转）
  → Response 200: { accessToken } + Set-Cookie: new refreshToken
  → Response 401: { error: "token 无效或已过期", code: "INVALID_REFRESH_TOKEN" }
      (同时清除客户端 refreshToken cookie)

GET /api/auth/me
  Header: Authorization: Bearer <accessToken>
  → 验签 + 查库确认 isActive
  → Response 200: { id, username, role, displayName }
  → Response 401: 用户已禁用或 token 无效

POST /api/auth/logout
  Cookie: refreshToken=<token>
  → 标记 refreshToken 为已撤销
  → Clear cookie
  → Response 204
```

**全局认证 + 错误格式**

```
全局 AuthGuard (JWT) — 所有端点默认需登录
  └── @Public() 装饰器豁免: /api/auth/login, /api/auth/refresh

统一错误响应: { error: string, code: string, statusCode: number }
  - 400: 参数校验失败 (class-validator)
  - 401: 未认证 / token 无效
  - 403: 角色无权限
  - 423: 账号锁定
  - 429: 速率限制
  - 500: 服务器内部错误 (HttpExceptionFilter 统一兜底)
```

**RBAC 实现**

```typescript
enum Role { LEGAL_BP = 'legal_bp', LEGAL_LEAD = 'legal_lead', BUSINESS = 'business', ADMIN = 'admin' }

// 全局注册
app.useGlobalGuards(new JwtAuthGuard(reflector), new RolesGuard(reflector));

@Controller('projects')
export class ProjectController {
  @Get()
  @Roles(Role.LEGAL_BP, Role.LEGAL_LEAD)
  async list(@CurrentUser() user: User) {}
}
```

**前端（Vue 3）**

```
路由守卫流程：
  访问任意页面
    → Pinia 中无 user → 尝试 GET /api/auth/me
        → 成功 → 存 user，按 role 跳转
        → 失败（无 refreshToken cookie 或 refresh 失败）→ /login
    → Pinia 中有 user → 检查 role 是否有权访问目标路由
        → 有权 → 继续
        → 无权 → 403 页面

三端首页映射：
  business   → /business/consult
  legal_bp   → /legal/projects
  legal_lead → /legal/projects
  admin      → /admin/dashboard

Pinia auth store:
  state: { user, accessToken }
  actions: login(), logout(), refreshAccessToken(), fetchMe()
  getters: isLoggedIn, currentRole
```

**数据库（Prisma Schema 新增）**

```prisma
enum Role {
  legal_bp
  legal_lead
  business
  admin
}

model User {
  id             String    @id @default(uuid())
  username       String    @unique
  passwordHash   String    @map("password_hash")
  displayName    String    @map("display_name")
  role           Role
  isActive       Boolean   @default(true) @map("is_active")
  failedAttempts Int       @default(0) @map("failed_attempts")
  lockedUntil    DateTime? @map("locked_until")
  createdAt      DateTime  @default(now()) @map("created_at")
  updatedAt      DateTime  @updatedAt @map("updated_at")

  loginAudits    LoginAudit[]
  refreshTokens  RefreshToken[]

  @@map("users")
}

model RefreshToken {
  id        String   @id @default(uuid())
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  userId    String   @map("user_id")
  jti       String   @unique
  tokenHash String   @map("token_hash")
  isUsed    Boolean  @default(false) @map("is_used")
  isRevoked Boolean  @default(false) @map("is_revoked")
  expiresAt DateTime @map("expires_at")
  createdAt DateTime @default(now()) @map("created_at")

  @@index([userId])
  @@index([jti])
  @@index([expiresAt])
  @@map("refresh_tokens")
}

model LoginAudit {
  id        String   @id @default(uuid())
  user      User     @relation(fields: [userId], references: [id])
  userId    String   @map("user_id")
  ip        String?
  createdAt DateTime @default(now()) @map("created_at")

  @@map("login_audits")
}
```

## Open Questions

- 种子用户密码明文在 seed.ts 中，生产部署前需改为环境变量注入 + 首次登录强制改密
- `localStorage` vs `httpOnly cookie` 的选择：评审决定 accessToken 存 Pinia 内存 + refreshToken httpOnly cookie。需要确保 Nginx 正确代理 cookie（`proxy_set_header Cookie $http_cookie`）
- SSO "只替换 AuthService" 过于乐观——v0.1.0 对接时还需处理身份绑定、用户同步、组到角色映射

## Success Criteria

- [ ] 4 个种子账号分别登录，各自进入对应端的首页
- [ ] legal_bp 访问 /admin/dashboard 返回 403
- [ ] accessToken 过期后 refreshToken cookie 自动续期，用户无感知
- [ ] 连续 5 次错误密码后第 6 次返回 423，等待 30 分钟后可正常登录
- [ ] refreshToken 使用一次后旧 token 失效（重放保护）
- [ ] 已禁用用户（isActive=false）的 accessToken 被 /me 拒绝
- [ ] 退出登录后 refreshToken cookie 清除，无法 refresh
- [ ] 登录成功记录到 LoginAudit
- [ ] 每 IP 超过 5 次/分钟请求 /login 返回 429
