## 范围（已确认）

完整实现（~15 文件、2 个新服务）：真实钉钉适配器 + 管理端成员管理模块 + 意图识别匹配 BP + 转派加人。

## 架构图

```
┌─ 配置期（管理端一次性）──────────────────────────────┐
│ MembersController (admin)                            │
│   POST /admin/members/sync   → DingTalkAdapter       │
│     syncContacts(): 部门树 → user/list 分页 → 去重    │
│     → 写入 dingtalk_contacts 快照表                   │
│     → 按 displayName 匹配 User → 写 dingtalkUserId    │
│   POST /admin/members/bind   手动绑定（快照搜索）      │
│   PUT  /admin/bp-domains      BP×6领域映射 CRUD       │
│   GET  /admin/members/failures  拉群失败工单计数      │
└──────────────────────────────────────────────────────┘
┌─ 运行期（每次建工单）────────────────────────────────┐
│ create()                                            │
│   ├─ riskService.assess() → {risk, route, domain}    │
│   │    （domain 仅当无技能时由 LLM 输出）             │
│   ├─ route==='legalbp' 且可解析领域?                 │
│   │   → BpDomainMap 匹配 → legalBpId 指派            │
│   ├─ 建群（同步 await，10s 超时，重试 1 次）          │
│   │   成员 = creator.userid + BP.userid              │
│   │   （无法务成员 → 不建群 + 事件"请人工建群"）       │
│   │   ownerUserId=creator → 群名截断 ≤20 字           │
│   └─ 首条消息（/v1.0/robot/groupMessages，纯文字）    │
├─ 升级（createMessage route→legalbp，异步）            │
│   └─ 复用完整匹配链 → 补建群                          │
├─ 转派（transfer/update/reply 三处共用检测）            │
│   └─ legalBpId 变更 → addMember（旧 BP 留群）         │
│   update() 补角色校验：legalBpId 仅 legal_bp/lead     │
└──────────────────────────────────────────────────────┘
```

## 实施步骤

**Step 0 — 联调 spike（先于一切代码，验证 3 个可行性前提）**
1. gettoken（AppKey/Secret 换 token）✓ 通讯录权限确认
2. user/list 分页拉通讯录（含 mobile 权限验证）
3. 建群 v2 参数 + robotCodes 进群 + 首条消息时序
输出：spike 结论文档；失败则按 Open Questions 回退场景群接口

**Step 1 — 数据层**（schema.prisma + migration）
- User 加 `dingtalkUserId String?`（+phone 副产物）
- 新表 `BpDomainMap`（userId, domain, unique(userId,domain)）
- 新表 `dingtalk_contacts`（快照：userid/name/mobile/updatedAt）
- seed：displayName 规范化（法务BP-张三 → 彭宇欣）

**Step 2 — 适配器**（dingtalk.adapter.ts，替换 Mock 绑定）
- gettoken 内存缓存（expires_in 提前 5 分钟刷新，401 重试 1 次）
- syncContacts（部门遍历→分页→去重）
- createGroup / addMember / sendGroupMessage
- Mock 保留（DINGTALK_MOCK=true fallback）

**Step 3 — 服务层**
- LLMRiskService：双标签输出（risk + domain 白名单约束）
- project.service：create 建群链 / 升级补建群（异步）/ 三处转派检测 / update 角色校验 / 事件记录
- MembersService + Controller（同步/绑定/映射/失败计数）

**Step 4 — 管理端页**（MembersView.vue + 路由 + admin 权限）

**Step 5 — 测试**（见测试计划）

## NOT in scope

- 双向消息/机器人回调/审批流（v1 已确认）
- 钉钉群消息中的链接（用户裁决：纯文字）
- 群成员移除/旧 BP 移出（用户裁决 T3：留群）
- 同领域多 BP 负载均衡（v2）
- 工作通知 API 推送（用户裁决 T1：保持拉群）
- 钉钉侧回调鉴权（无回调入口）

## 测试计划（对齐覆盖图）

单测（vitest，与现有 skill/contract 测试同构）：
1. **dingtalk.adapter.spec.ts**：gettoken 成功/失败/缓存/401 刷新；syncContacts 多页拼接 + userid 去重；createGroup 成功/失败/群名截断/坏成员剔除重试；addMember；sendGroupMessage
2. **llm-risk.spec.ts**：双标签输出（白名单内/外/失败）；**回归**：现有 risk 分级 P0/P1/P2 不回归；风险解析失败默认 P1
3. **project-skill-dingtalk.spec.ts**（或新 spec）：create legalbp 匹配 BP→指派→建群；技能 group 优先领域；匹配失败→兜底负责人；**无法务成员→不建群+事件**；建群失败→不阻断+事件；create llm **回归**：不拉群不匹配；升级补建群（异步触发）；transfer/update/reply 三处转派加人（变更/无变更/未绑定跳过）
4. **members.spec.ts**：同步端点（权限/去重/快照落库/姓名匹配/重名落手动）；绑定；BP 映射 CRUD；失败计数

LLM A/B 评估用例（对齐技能库门禁）：领域分类 10 例（6 领域各 1-2 + 边界 2）双跑（技能 group vs LLM 标签），通过标准：白名单内标签 ≥9/10

前端：MembersView 手动 QA（同步按钮/绑定搜索/映射编辑/失败计数）

## Failure modes

| 场景 | 测试 | 错误处理 | 用户可见 |
|------|------|----------|----------|
| 建群 API 失败 | ✓ | try/catch + 事件"请人工建群" | 事件可见 |
| 建群成功但落库失败（孤儿群） | ✓ | 重试 1 次；群名带工单号可辨 | 事件可见 |
| 机器人进群未生效，首条消息失败 | ✓ | 事件"群已建但首条消息发送失败" | 事件可见 |
| 全部成员未绑定 | ✓ | 不建群 + 事件"请人工建群" | 事件可见 |
| 转派加人失败 | ✓ | 事件记录 | 事件可见 |
| LLM 分类失败 | ✓ | 默认 P1/legalbp + 领域未匹配兜底 | 事件可见 |
| 管理端同步失败 | ✓ | 错误提示 + 重试 | 页面提示 |
