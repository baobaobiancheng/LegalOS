## 一、产品概述

### 1.1 产品定位

法务AI平台是面向企业的轻量化法务协同工作台，通过 **统一入口 + 三端（法务端 / 业务端 / 管理端）** 架构，打通业务法律咨询、合同审核协作、法规检索的完整闭环。v0.0.1 聚焦工单流程闭环、钉钉打通和 Skill 库三大核心能力，后续版本逐步引入 AI 数字分身和知识库体系。

### 1.2 当前痛点

| 痛点 | 现状 | 目标 |
|------|------|------|
| 入口分散 | 业务人员通过 CRM、钉钉、邮件、文档工具分别获取法务支持，效率不稳定 | 业务端统一入口，不跳转系统即可完成全流程 |
| 重复劳动 | Legal BP 需重复处理大量标准问题，无自动化分流 | 风险分级 + 工单闭环，法务聚焦高价值工作（后续版本数字分身进一步提效） |
| 知识流失 | 优质口径、审查经验、业务反馈未形成可复用资产 | 工单留痕 + 结构化答复（后续版本自动知识沉淀） |
| 缺乏闭环 | 合同处理过程与结论难以回写业务系统 | CRM 上下文带入 + 结果回写，全链路可追溯 |
| 协作低效 | 法务与业务之间依赖即时通讯、邮件沟通，信息散落 | 钉钉自动拉群协作，工单内对话留痕 |

### 1.3 MVP 目标（v0.0.1）

v0.0.1 采取 **"先搭骨架、再长肌肉"** 策略：先搭建初始平台基础框架，然后优先落地工单流程闭环、钉钉打通和 Skill 库三个核心能力。

1. **初始平台搭建**：统一登录入口 + 三端路由框架（法务端 / 业务端 / 管理端），账号体系 + 权限控制
2. **工单流程闭环**：业务人员发起 → 自动风险判定 → P2 AI 辅助答复 / P1+P0 升级法务 BP → 法务处理 → 结果回传业务端
3. **钉钉打通**：工单创建时钉钉自动拉群协作，状态变更钉钉通知
4. **Skill 库**：6 大技能组 18 项技能上线，每个工单可选择对应技能优化 AI 处理效果
5. **业务法律咨询闭环**：覆盖 P0/P1/P2 全风险等级的咨询场景
6. **合同协作闭环**：模板选择 → AI 生成草稿 → 法务审阅 → 下载回传

### 1.4 不在 MVP 范围

- **AI 数字分身**（后续 v0.2.0 版本）— MVP 阶段 P2 咨询走基础 LLM 直答，不做分身配置、版本管理和复核抽检流程
- **知识库**（后续 v0.2.0 版本）— MVP 阶段工单回传后暂不做知识沉淀和知识库管理
- 企业 SSO 统一登录（MVP 阶段内网部署 + 基础账号体系）
- SRM、OA、在线文档、邮件等系统对接（后续通过通用接口扩展）
- 移动端适配
- 多语言支持

## 二、用户画像

### 2.1 角色定义

| 角色 | 所属端 | 典型用户 | 核心诉求 |
|------|--------|----------|----------|
| **业务人员** | 业务端 | 销售经理、采购专员、市场运营等 | "我有一个业务问题需要法务意见，越快越好，最好不用跳出当前工作流" |
| **法务 BP** | 法务端 | 对接业务线的法务 BP | "同时处理几十个工单，需要 AI 帮我写初稿，我只审核心部分" |
| **法务负责人** | 法务端 + 管理端 | 法务总监/经理 | "我需要知道团队处理了多少工单、数字分身准不准、哪些知识可以复用了" |
| **系统管理员** | 管理端 | IT / 平台运维 | "我能管用户账号、配 AI 模型、设定时任务" |

### 2.2 核心使用场景

```
业务人员（销售）
  ├─ 场景1：客户要求修改合同条款 → 业务端提交合同协作 → AI生成草稿 → 法务审阅 → 回传
  ├─ 场景2：不确定某营销活动是否合规 → 业务端发起咨询 → P2数字分身直答（1分钟内）
  └─ 场景3：数据出境问题 → 自动判定P1 → 法务BP接单 → 正式法务意见回传

法务 BP
  ├─ 场景1：收到P1咨询工单 → AI辅助分析+法规检索 → 复核AI草稿 → 正式回传
  ├─ 场景2：P2 LLM 直答复结果需要优化 → 修改后直接回传业务端
  ├─ 场景3：同事请假，工单转派给自己 → 查看工单上下文 → 继续处理
  └─ 场景4：自行发起法规检索 → 输入关键词 → 获取法条原文+AI释义

法务负责人
  ├─ 场景1：查看周报 → 关注P0工单处理情况 → 抽查法务BP答复质量
  ├─ 场景2：维护合同模板 → 新增/编辑模板 → 启用/停用（v0.1.0）
  ├─ 场景3：查看数据看板 → 团队工单量和响应时间统计（v0.1.0）
  ├─ 场景4：配置数字分身 → 设置回复口径和授权范围 → 试运行（v0.2.0）
  └─ 场景5：审核知识沉淀条目 → 批准写入企业知识库（v0.2.0）

系统管理员
  ├─ 场景1：创建新法务BP账号 → 分配角色 → 新同事即可登录法务端
  └─ 场景2：AI模型响应变慢 → 查看健康状态 → 切换备用模型
```

### 4.2 业务法律咨询（核心流程 1）

**需求描述**：业务人员提交法律问题，系统自动判断风险等级并分流。P2 由 LLM 直接生成 AI 答复，P1/P0 自动创建法务端工单由法务 BP 人工处理。

**流程**：

```
业务端发起提问
    │
    ▼
系统自动风险判定
    │
    ├── P2（常规风险）
    │       │
    │       ▼
    │   LLM 直答 ──→ AI 生成答复，即时返回业务端
    │   （v0.2.0 升级为数字分身直答 + 抽检复核）
    │
    ├── P1（重要风险）──→ 创建法务端工单 → 钉钉拉群 → 法务 BP 处理 → 回传
    │
    └── P0（紧急风险）──→ 创建法务端工单 + 紧急标记 → 钉钉即时通知 → 法务 BP 优先处理 → 回传
```

**功能点**：

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F-CONSULT-01 | 自由文本提问 | P0 | 业务人员用自然语言描述法律问题 |
| F-CONSULT-02 | 自动风险判定 | P0 | 基于关键词识别高风险场景（无限责任/数据出境/跨境/个人信息/诉讼/监管/并购/股权等）|
| F-CONSULT-03 | P2 LLM 直答 | P0 | 低风险问题由 LLM 直接生成 AI 答复，1 分钟内返回结果（v0.2.0 升级为数字分身） |
| F-CONSULT-04 | P1/P0 升级工单 | P0 | 高风险问题自动创建法务端工单，钉钉拉群通知法务 BP |
| F-CONSULT-05 | 多轮对话 | P0 | 同一会话内保留全部对话历史，支持追问和澄清 |
| F-CONSULT-06 | AI 答复结构化 | P0 | 按"核心结论 → 重点风险 → 建议动作 → 需补充确认"四段式输出 |
| F-CONSULT-07 | 回传机制 | P0 | 法务处理结果自动回传至业务端原始会话 |
| F-CONSULT-08 | 服务不可用提示 | P1 | LLM 不可用时提示"服务暂不可用，请联系法务平台管理员" |
| F-CONSULT-09 | 满意度评价 | P2 | 业务端对 AI 直答和法务人工答复分别评分 |

**风险判定规则（MVP）**：

| 风险等级 | 关键词（包含任一即触发） | 处理方式 |
|----------|--------------------------|----------|
| P0 紧急 | 刑事责任、监管调查、紧急禁令、重大安全事故 | 创建工单 + 紧急标记 + 即时通知 |
| P1 重要 | 无限责任、数据出境、跨境、个人信息、诉讼、监管、并购、股权、竞业 | 创建工单，正常流程处理 |
| P2 常规 | 其他所有情况 | LLM 直答，即时返回 |

### 4.3 合同协作（核心流程 2）

**需求描述**：业务人员选择合同模板 → 输入关键要素 → AI 生成合同草稿 → 下载为 .docx 或发起法务审阅 → 法务审阅 → 回传定稿。

**流程**：

```
业务端发起
    │
    ├─ 选择合同模板（渠道合作/技术服务/保密协议）
    │
    ├─ 输入合同关键要素
    │       │
    │       ▼
    │   AI 生成合同草稿
    │       │
    │       ├─ 下载 .docx（业务人员自行处理）
    │       │       │
    │       │       └─ 本地编辑后上传回传 → 继续审阅
    │       │
    │       └─ 创建合同协作工单 → 法务端审阅
    │               │
    │               ▼
    │           法务 BP 审阅（AI 辅助风险审查）
    │               │
    │               ▼
    │           法务定稿 → 回传业务端 → .docx 下载
    │
    └─ 上传新旧版本 → 条款差异比对
```

**功能点**：

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F-CONTRACT-01 | 合同模板选择 | P0 | 内置渠道合作协议、技术服务合同、保密协议 |
| F-CONTRACT-02 | 需求输入 | P0 | 业务人员输入关键要素（对方主体、金额、期限、主要条款等） |
| F-CONTRACT-03 | AI 生成草稿 | P0 | 基于模板 + 要素生成合同草稿 |
| F-CONTRACT-04 | 合同协作工单 | P0 | 创建合同协作项目，发送至法务端 |
| F-CONTRACT-05 | AI 风险审查 | P0 | AI 对合同条款进行风险识别和提示 |
| F-CONTRACT-06 | 合同下载 | P0 | 草稿/定稿支持 .docx 下载 |
| F-CONTRACT-07 | 合同回传 | P0 | 本地编辑后上传，继续审阅流程，形成协作闭环 |
| F-CONTRACT-08 | 条款差异比对 | P1 | 上传新旧版本，AI 自动标注条款变更 |
| F-CONTRACT-09 | 合同模板管理 | P1 | 法务负责人自定义维护模板库 |

```
       待复核
          │
          ├──→ 已回传 ──→ 通知业务端 + 钉钉群同步
          │
          ├──→ 待复核（继续修改）
          │
          └──→ 已取消（业务撤回）
```

**功能点**：

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F-TICKET-01 | 工单创建 | P0 | 支持业务咨询、合同协作、法律检索、文书生成 4 种类型 |
| F-TICKET-02 | 工单状态流转 | P0 | 分析中 → 待复核 → 已回传 / 待处理（失败）/ 已取消 |
| F-TICKET-03 | 风险分级标签 | P0 | P0（紧急）/ P1（重要）/ P2（常规）|
| F-TICKET-04 | 工单列表 | P0 | 按状态分组：待处理、合同协作、已回传、数字分身处理 |
| F-TICKET-05 | 对话式交互 | P0 | 多轮对话，消息角色：用户/助手/法务/事件通知 |
| F-TICKET-06 | CRM 上下文 | P0 | 工单带入 CRM 客户/商机/合同编号等业务上下文 |
| F-TICKET-07 | 钉钉自动拉群 | P0 | 工单创建后自动在钉钉建群，拉入法务 BP + 业务人员 + 接口人 |
| F-TICKET-08 | 工单转派 | P1 | 法务 BP 之间转派（请假、专业不匹配等场景） |

### 4.5 法规检索

**需求描述**：法务端专属功能。对接国家法律法规数据库（flk.npc.gov.cn），检索现行有效法规原文并结合 AI 释义。

**功能点**：

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F-LAW-01 | 关键词检索 | P0 | 对接 flk.npc.gov.cn，按关键词搜索现行有效法规 |
| F-LAW-02 | 原文获取与法条定位 | P0 | 下载并解析 DOCX 原文，定位到具体法条号（如"第十条"） |
| F-LAW-03 | AI 法律释义 | P0 | 按"法条原文 / 法律分析 / 需确认事实"三段式输出 |
| F-LAW-04 | 来源追溯 | P0 | 附带法规标题、制定机关、效力状态、官方链接 |
| F-LAW-05 | 效力状态标注 | P1 | 标注现行有效 / 已废止 / 已修改 / 尚未生效 |

### 4.6 AI 数字分身（后续版本 v0.2.0）

> ⚠️ **v0.0.1 不做**。MVP 阶段 P2 咨询走基础 LLM 直答，不做分身配置、版本管理和复核抽检。数字分身完整能力规划如下，计划在 v0.2.0 上线。

**需求描述**：可配置的 AI 法务助手，自动处理 P2 级别常规法律咨询。底层对接李帅团队分身能力，本平台负责配置管理和业务集成。

| 编号 | 功能 | 说明 |

| F-TWIN-02 | 回复口径设置 | 定义回复风格和口径边界 |

### 4.7 技能库（v0.0.1 核心）

**需求描述**：按法务实务领域组织的 AI 技能体系，是 v0.0.1 三大核心目标之一。每个工单创建时必须选择对应技能，系统根据技能 prompt 优化 AI 处理效果。

| 技能组 | 包含技能 | v0.0.1 |
|--------|----------|:---:|
| 合规法务 | 数据合规评估、营销授权核验、AI 研发合规 | ● |
| 合同与交易 | 合同风险审查、条款差异比对、交易结构设计 | ● |
| 劳动法务 | 员工关系咨询、竞业限制评估、用工风险体检 | ● |
| 争议法务 | 争议焦点识别、证据链构建、类案检索 | ● |
| 法律研究 | 法规原文检索、效力状态核验、新法影响分析 | ● |
| 知识运营 | 知识条目沉淀、制度问答、工单复盘 | ● |

> **共 6 大技能组、18 项技能，v0.0.1 全部上线。** 每项技能对应一套 system prompt 模板，按技能类型优化 AI 的输出结构和专业方向。

### 4.8 知识库（后续版本 v0.2.0）

> ⚠️ **v0.0.1 不做**。MVP 阶段工单回传后不自动进入知识沉淀队列，知识库管理功能整体后移到 v0.2.0。完整规划如下。

**需求描述**：企业法律知识的沉淀、管理与引用体系。已回传的优质工单 → 待沉淀队列 → 法务负责人审核 → 写入企业知识库。

| 编号 | 功能 | 说明 |
|------|------|------|
| F-KB-01 | 企业知识库 | 受控共享的知识条目，状态分"受控发布"和"待审核" |

| F-KB-03 | 知识条目管理 | 支持标题、描述、标签、状态管理 |

| F-KB-07 | 个人→企业提交 | 个人知识提交至企业库，经法务负责人审核后发布 |
| F-KB-08 | 工单知识引用 | 工单处理时引用知识库条目 |
| F-KB-09 | 知识沉淀队列 | 已回传的优质工单自动进入待沉淀列表，经审核后写入企业知识库 |
