## 一、外部评审（ChatGPT + GPT）逐条核实与采纳

- 认证变量 **`CODEX_API_KEY`**（非 `OPENAI_API_KEY`），`env_key` 读取
- **`wire_api` 官方只支持 `"responses"`** → 网关必须实现 `POST /v1/responses`
- **`approval_policy="never"` 不等于拒绝命令**，拦截靠沙箱权限
- **`shell_environment_policy.inherit="none"`** 必须加，防子进程 printenv 泄密
- **优先 read-only 权限档案**（非 workspace-write）
- **`deny_read` 用字面路径**，弃需要遍历无权限目录的 glob（实测 EACCES 弄坏沙箱）
- **HTTPS 议题**：网关当前仅 HTTP:80，已列入待网关团队确认
- 部分建议针对旧代码（环境白名单已实现）——澄清后无改动

## 二、服务器根因排查（一段长链条）

1. **摸底发现 codex 从未配过认证**：`.env` 无 codex 变量、`~/.codex` 无 auth.json → 服务器 AI 从没跑通过（Windows 能跑是因沙箱/CODEX_HOME 解析机制不同）
2. **`HOME: workspaceDir` 覆盖是 Unix 认证失效根因**：实测 codex 的 `CODEX_HOME` 跟着 HOME 走 → 指向被清理的临时目录
3. **bwrap 0.6.1 不支持 `--argv0`** → codex fallback 把 helper 变裸名 PATH 查找 → 沙箱整体起不来（默认配置也一样坏）→ **源码编译 bwrap 0.11.0** 修复
4. **`CODEX_HOME` 目录必须预建**（codex 报 `path does not exist`）→ 硬化模式预建 `workspaceDir/.codex`
5. **deny_read glob 陷阱**：`/root/.codex`、`/home/*/.codex` 等触发 EACCES → 收窄为字面路径
6. **`codex sandbox` 需 `--include-managed-config`**（显式选档案时默认不含受管配置）
