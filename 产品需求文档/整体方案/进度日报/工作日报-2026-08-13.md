## 一、根因定位：风险分类走 Codex CLI 卡满 90s

- **现象**：咨询「发了不回复，过一会请求超时」。
- **根因链**：建单/追问前 `LLMRiskService` 走 `CodexService.execute`(Codex CLI 子进程)，而正文走直连网关正常 → 日志 `Codex execution timed out`。**`maxTokens` 是假配置**(CLI 未接收)，分类时长不可控。
- 证据：正文 `consult-chat 完成` 4~68s 正常，分类 `Codex execution timed out` 90s 超时。

## 二、风险分类改直连网关 + 关闭思考(核心突破)

- **`ConsultationChatService.complete()`**：非流式直连网关单次调用(契约 C1/C2)，短超时 + 小 maxTokens，绕开 Codex CLI。
- **`LLMRiskService` 改用 complete()**，删除 `CodexService` 依赖 + `CodexOptions.maxTokens` 假配置。
- **关闭思考(关键)**：实测 `thinking.type=disabled` / `enable_thinking=false` / `reasoning_effort=none` 均无效，**`chat_template_kwargs: { enable_thinking: false }` 生效**(vLLM 后端)。实测：`reasoning=null`、`content` 直接出 JSON、`completion_tokens 7`(原 487)、**耗时 0.7s(原 8-11s)**。
- 分类预算随之下调：12000→4000→**1000**、超时 30s→20s→**10s**。
- 提交 `edb0544`、`ce55f51`、`d0cb312`、`07f3684`。

## 四、前后端输入限制一致 + 取消限制

- 根因：前端 `canSend` 只要求 `>0` 能发，后端 `CreateProjectDto` `@MinLength(5)` 拒 → 短句(如「你好」)前端能发后端报 `title/input <5 字符`。
- 先对齐(前端 ≥5)，后**完全取消**：后端移除 `@MinLength(5)` 只留 `@IsNotEmpty` + `@MaxLength`，前端只留非空。
- 提交 `bccb355`、`2a8a318`。

## 五、服务器部署规范化(解决「我正常别人不生效」)

- **根因**：`http://192.168.162.170`(不带端口)走 nginx :80 → `/var/www/html` 默认页，**不是 LegalOS**；只有 `:5173`(vite dev)才是系统。别人访问 80 看到的是默认页。
