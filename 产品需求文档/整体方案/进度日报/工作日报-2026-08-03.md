## 二、关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 合同协作架构 | Approach A（复用 Project + 最小新增） | 闭环完整、复用最大化，唯一新增是模板表+文件存储 |
| 生成草稿建单 | 绕过 ProjectService.create() 直接建单 | create() 写死风险判定+咨询 prompt，不可复用 |
| 模板导出格式 | 每模板独立 style JSON + 前端参数化 | 3 个真实模板格式各异（楷体系/字号/页边距），非全局统一 |
| AI 补全策略 | 铁律不编造（未提供标【待补充】） | 法律合同编造实事 = 重大风险，用户核心诉求 |
| 模板参照 | 模板 md 进 Codex 工作区 + 指示读取 | 不注入 prompt（token 开销）、保持工作区隔离 |
| 文件存储 | 本地磁盘 + 备份策略（不存 DB） | MySQL 不是文件系统，DB 存元数据、文件存存储层 |
| 生成超时 | 600s + 客户端断开不 kill | 完整合同生成 2-4 分钟，断开≠失败 |
